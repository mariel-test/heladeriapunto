BUG-003 frontend/style.css
.grid-productos		 En la pantalla "¿Qué tamaño?", al hacer hover sobre las tarjetas de la fila superior, el header las cubría visualmente.

Causa raíz: .grid-productos tenía overflow-y: auto, que convierte el grid en un scroll container. Ese contenedor recorta cualquier contenido que supere su borde superior, incluyendo el transform: translateY(-3px) del efecto hover — los 3px que la tarjeta sube quedan ocultos exactamente donde está el header.

Pendiente de corrección. Este defecto fue identificado por el equipo de QA (automatización de pruebas). La corrección implica modificar el layout CSS de .grid-productos en style.css y requiere intervención de un desarrollador frontend. El equipo de QA no tiene rol de desarrollo frontend y no está en condiciones de aplicar el fix sin riesgo de introducir regresiones visuales. 		Reporte manual

label .filtro-tacc		 El checkbox de filtro mostraba la etiqueta "Filtrar sin TACC", redacción semánticamente incorrecta: el filtro muestra los sabores aptos para celíacos (con certificación sin TACC), no los que "no tienen TACC". BUG-004 backend/ · DATABASE_URL
Configuración de conexión a PostgreSQL		 Los pedidos no se persistían en la base de datos.

Causa raíz — dos problemas encadenados:
  1. El nombre de la base de datos en DATABASE_URL no coincidía con el nombre real con el que fue creada la BD.
  2. La contraseña del usuario admin había sido reseteada al recrear el contenedor de PostgreSQL, dejando la conexión del backend inválida.
Ambos problemas hacían que el backend fallara silenciosamente al intentar persistir el pedido.

Síntoma: la UI mostraba "✓ Pedido confirmado" pero el registro no existía en BD y GET /pedido/{id} devolvía 404.

Fix: corregido DATABASE_URL en .env (nombre de BD y contraseña correctos). TC-E2E01 fue reforzado para verificar persistencia real vía GET /pedido/{id}; se añadió TC-PD13 (TC-26) en la suite API para cubrir todos los campos del pedido persistido. 		TC-E2E01
